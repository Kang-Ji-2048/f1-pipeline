# Live Ingestion, Dashboard & Deployment — Implementation Plan

**Goal:** Extend the F1 pipeline with a real-time live-polling ingest mode, an interactive Streamlit dashboard, Docker containerisation, and AWS (EC2/S3) deployment-readiness, on top of the existing batch pipeline.

**Architecture:** Keep the existing `src/api` → `src/models` → `src/pipeline` → `src/db` layering. Add: a live-polling ingest path reusing the idempotent `_upsert_batch`; dashboard-specific read methods on `F1Database` consumed by a Streamlit app; a boto3-based S3 export command; Docker + compose + an EC2 runbook.

**Tech Stack:** Python 3.11+, httpx, Pydantic v2, SQLAlchemy 2.0, Click, structlog, Streamlit, Plotly, boto3, Docker, PostgreSQL 16.

## Global Constraints

- Keep `mypy --strict`, `ruff check src/ tests/`, `ruff format --check src/ tests/`, and `pytest` green after every task.
- Never modify existing `#` comments in the codebase (repo CLAUDE.md).
- TDD: failing test first for all new pure/business logic. Streamlit UI and Dockerfiles are verified manually, not unit-tested.
- New heavy deps go behind optional extras: `[dashboard]` (streamlit, plotly), `[aws]` (boto3).

## Notes discovered during execution

- The build backend was invalid (`setuptools.backends._legacy:_Backend`), breaking `pip install`; fixed to `setuptools.build_meta`.
- setuptools discovered no packages, so the install was empty and the console script failed; fixed with `[tool.setuptools.packages.find] include=["src*"]`.
- `alembic/versions/` was empty (`alembic upgrade head` was a no-op); added an autogenerated initial migration.
- The Ergast mirror rate-limits at ~4 req/sec; added a request throttle plus `429 Retry-After` handling in the HTTP client.
